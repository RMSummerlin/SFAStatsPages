# Pace Statistics

Offensive tempo and play volume by team, with filters for week, quarter, down,
venue and huddle. Two metric groups behind a toggle:

- **Tempo** — play clock used, neutral play clock used, gear change, no-huddle rate
- **Volume** — plays per game, opponent-adjusted plays per game, plays per drive, drives per game, time of possession

Tempo is **play clock used**: 40 minus the seconds left on the play clock at the
snap. Lower is faster. It replaced snap-to-snap timing because snap-to-snap also
counts how long the previous play took to finish, which is not a tempo decision —
see `docs/pace-data.md`.

Cells are shaded by rank on the column, teal for the fast/high end and Sharp red
for the slow/low end. Teal rather than green on purpose: red against green is the
one pairing a meaningful share of the audience cannot separate, and teal carries
the same reading while staying distinct under deuteranopia.

Team names come in three widths — full name, nickname, abbreviation — chosen from
the **container** width via `ResizeObserver`, not the viewport, so a tool dropped
into a narrow column still labels itself sensibly.

Expanding a team row shows its pace by score margin against the league average,
and its pace week to week.

## Seasons

The Season control is multi-select, matching the personnel tool. Picking several
years pools them into one set of rows rather than showing them side by side, so
"2021–2025" is a five-year career-style view of each offense, not five tables.

Season files are fetched the first time a year is selected and cached after that,
so switching back and forth costs nothing. Season is the one filter that cannot
be emptied — deselecting the last year re-selects it — and **Reset does not touch
it**, because silently reloading four extra seasons is a surprising thing for a
Reset button to do. The popover's own button is labelled "Latest" instead of
"Clear" for the same reason.

Franchise codes are normalised in `pull_pace.py` before anything is published, so
a multi-season view always shows 32 rows. Washington folds `WFT` and `WSH` into
`WAS`, Las Vegas takes `OAK`, the Chargers take `SD`, the Rams take `STL` and
`LA`, and a set of provider-specific spellings (`JAC`, `ARZ`, `BLT`, `CLV`,
`HST`, `KAN`, `NOR`, `SFO`, `GNB`, `NWE`, `TAM`) fold onto the current code.

Every fold is printed in the Actions log, e.g. `2021: pooled WFT → WAS (2,040
team-play references)`, and any season that does not come out at exactly 32 teams
prints its team list with a pointer to `TEAM_ALIASES`. If a sheet turns up with a
spelling that is not in the map, that is how you will find out.

## Data source

Fetches from GitHub Pages:

- `data/pace_index.json` — which seasons have tempo data, and the default
- `data/pace_<season>.json` — the encoded play and drive tables for one season,
  fetched on demand as seasons are selected

Both are generated by `scripts/pull_pace.py`. See `docs/pace-data.md` for how
the metrics are defined and why.

The index only lists seasons whose sheet actually carries `TimeSinceSnap`, so
the season picker never offers a season that would render empty. A season starts
appearing the moment that column exists in its sheet — no change to this tool.

## Embedding

Paste the whole of `tool.html` into an Avada custom code block. It is a fragment:
one `<style>`, one `<div class="pt-root pt-pc">`, one `<script>`.

The second class matters. `.pt-root` alone is shared with every other tool in
this repo, so a rule like `.pt-root .pt-grid th {}` would reach into the
personnel tool as well. Every selector here is scoped `.pt-root.pt-pc`.

Run `python scripts/lint_embed.py tools/pace/tool.html` before pasting.

## Things that will look like bugs but are not

**A dash instead of a number.** Gear change needs at least 75 plays on both
sides of the comparison. At season level every team clears that comfortably, so
dashes only appear once a filter narrows things down — for example filtering to
quarter 1 leaves most teams short of 75 trailing plays.

**Neutral is empty under a quarter 4 or OT filter.** Neutral is defined as
quarters 1 to 3, so the intersection is genuinely empty. A dash is the honest
answer.

**Small differences between teams.** The whole league fits inside about five and
a half seconds. That is the real spread, not a rendering problem. The shading is
scaled by rank rather than by raw value so the full colour range is always used —
which means the colours show *order* reliably but should not be read as showing
*distance*. The numbers themselves do that.

**Washington's no-huddle rate is enormous.** 61% against a 9.9% league average.
It comes through that way in the source data. See the note in
`docs/pace-data.md`.

**Sorting looks backwards on some columns.** Lower play clock used is faster, so
rank 1 is the smallest number; higher plays per game is more, so rank 1 is the
largest. Each column carries its own direction, and the rank column always shows
the team's standing on the sorted column — so reversing the sort counts 32 down
to 1 rather than renumbering the rows.

## Refreshing the crawlable table

The static table inside the `SFA:PRELOAD` markers is what search engines see.
Regenerate it after a data pull with:

```
python scripts/refresh_preload.py
```

then re-paste `tool.html` into Avada. Worth doing every week or two in season.

## Convergence with the personnel grouping tool

Both tools deliberately behave the same way, so a reader who learns one is not
surprised by the other:

- Filter options apply on tap, with the popover left open. There is no Apply step.
- Each popover has its own **Reset**; the bar has **Clear all**, which also returns the
  season scope to the newest season.
- The rank column header is `#`.
- Column headers carry their full text in the DOM with the unit on a second line, so a
  crawler sees "Play Clock Used (Sec/Play)" rather than an abbreviation. The old version
  swapped in a short label below a width threshold, which meant anything rendering
  without layout only ever saw the short form.
- The metric formerly labelled "Neutral" is now **Neutral Script**, because "neutral
  script" is a filter in the personnel tool and the same word meaning two things across
  two tools on one site is a comprehension problem.
